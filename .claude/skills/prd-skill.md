# PRD (Product Requirements Document) Skill

사용자의 아이디어를 비즈니스 관점의 제품 요구사항 문서로 변환하는 워크플로우.

## 핵심 원칙

**비즈니스 가치와 사용자 관점에 집중한다.** 기술적 구현 방법은 TRD에서 다룬다.

## PRD 작성 프로세스

### Phase 1: 제품 비전 정의

1. "이 제품이 해결하려는 핵심 문제는 무엇인가요?"
2. "성공을 어떻게 측정할 건가요?" (KPI/메트릭)
3. "경쟁 제품 대비 차별점은 무엇인가요?"

### Phase 2: 사용자 분석

1. "주요 타겟 사용자는 누구인가요?"
2. "사용자의 페인 포인트는 무엇인가요?"
3. "사용자 여정(User Journey)을 설명해주세요"

### Phase 3: 기능 우선순위

1. "반드시 있어야 하는 기능(Must-have)은?"
2. "있으면 좋은 기능(Nice-to-have)은?"
3. "명시적으로 제외할 기능(Out of scope)은?"

### Phase 4: 비즈니스 제약

1. "출시 목표 일정이 있나요?"
2. "예산 제약이 있나요?"
3. "법적/규제 요구사항이 있나요?"

## PRD 질문 규칙

- 비즈니스 언어로 질문한다 (기술 용어 최소화)
- 사용자 스토리 형식으로 요구사항 정리
- 우선순위를 명확히 구분한다 (P0/P1/P2)
- 성공 기준(Acceptance Criteria) 포함

## 워크플로우 예시

```
사용자: "쇼핑몰 PRD 작성해줘"

Claude: "쇼핑몰 제품 요구사항을 정리하겠습니다.

1. 이 쇼핑몰이 해결하려는 핵심 문제는 무엇인가요?
   - 기존 쇼핑몰의 어떤 불편함을 개선하려는지
   - 타겟 시장(의류, 식품, 전자제품 등)은 무엇인지"

사용자: "수제 공예품 판매자들이 쉽게 온라인 판매를 시작할 수 있게 하고 싶어요"

Claude: "수제 공예품 마켓플레이스군요! 추가 질문입니다.

2. 주요 사용자 그룹을 정의해주세요.
   - 판매자: 어떤 규모? (개인/소규모 사업자)
   - 구매자: 주요 연령대나 특성이 있나요?"

... (인터뷰 계속) ...
```

## PRD 완료 후

PRD 확정 후 다음 단계 제안:

1. "TRD(기술 요구사항) 작성을 시작할까요?"
2. "특정 기능에 대해 더 상세한 정의가 필요한가요?"
3. "이해관계자 리뷰가 필요한 부분이 있나요?"

## PRD vs SPEC.md 차이점

| 구분 | PRD | SPEC.md |
|------|-----|---------|
| 관점 | 비즈니스/제품 | 기술/구현 |
| 대상 | PM, 이해관계자 | 개발팀 |
| 내용 | What & Why | How |
| 상세도 | 요구사항 수준 | 구현 수준 |
